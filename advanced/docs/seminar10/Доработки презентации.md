# Доработки презентации семинара 10 — продвинутый трек

## Основа и границы изменений

`seminar11.pptx` рядом — неизменённый оригинал прошлого года. Используем именно его структуру,
вопросы аудитории и иллюстрации. Это исходник для последующего редактирования; перечисленные
ниже изменения пока в PPTX не внесены. Ранее собранную «Семинар 10 (advanced).pptx» используем
как источник дополнительных объяснений, а не как основу последовательности.

Семинар: около часа на платформенные потоки, затем 30–60 минут на JMM. Без обзора пулов,
синхронизаторов и concurrent-коллекций. Бизнес-задача — после теории, код показываем в IDE.

## Изменения по исходным слайдам

| Слайды | Предлагаемые изменения |
|---|---|
| 1–3 | Номер 10, актуальная дата и план. На дорожной карте: 10 — потоки/JMM, 11 — Executor/Future/CompletableFuture, 12 — виртуальные потоки. Убрать устаревшее упоминание Java 19 как версии появления Loom API. |
| 5–8 | Сохранить картинки видов потоков, планировщика и жизненного цикла. Добавить 1:1 и краткое сопоставление с M:N через носители. Развести независимые классификации platform/virtual и daemon/non-daemon. Ready/Running входят в JVM RUNNABLE; состояния ОС и JVM не совпадают. BLOCKED в JVM относится к входу в монитор, а не ко всякому ожиданию ресурса. |
| 10–12 | Сохранить примеры Runnable, конструктора и builder. Убрать утверждение об устаревании конструктора. Кратко пояснить start против run, однократность start, sleep против join. Приоритет — подсказка, без гарантии порядка и доли CPU. |
| 13–14 | Дополнить ожидания park/unpark: один permit, повторная проверка условия. Исправить прямую стрелку interrupt → завершение: отмена кооперативная. Показать проверку/очистку флага и реакцию разных ожиданий на interrupt. |
| После 14 | Добавить исключение, вышедшее из run: раскрутка стека, finally и освобождение мониторов → UncaughtExceptionHandler → TERMINATED. Обработчик выполняется в падающем потоке; start/join ошибку не перебрасывают. Индивидуальный и default handler, стандартный путь через ThreadGroup. Обработчик не продолжает выполнение после ошибки. |
| 15, 24, 41 | Сохранить переходы в IDE, убрать ссылки на старые пакеты и скриншот окружения. Подписать тему показа. |
| 17–22 | Сохранить задачу двойного списания, картинки монитора и wait/notify. Подчеркнуть атомарность всей проверки с изменением. Добавить while вокруг wait; notify не передаёт монитор, пробуждённый поток захватывает его повторно. |
| 23, 42 | Убрать слайды самостоятельного чтения; материалы выдаём отдельно. |
| 27–30 | Сохранить вопрос аудитории, поэтапное раскрытие и исходный двухпоточный пример. Заменить обвязку с sleep(100) и старый вывод на jcstress и подготовленные результаты. Не выдавать частоты исходов одного запуска за гарантии. |
| 31–35 | Сохранить мотивировку через оптимизации и картинку иерархии памяти. Дополнить буфером записей/JIT; coherence не даёт общего порядка по всем переменным. JMM — правила допустимого поведения, а не схема кешей. Схемы чередований не исчерпывают все допустимые исходы. |
| 36–40 | Сохранить volatile-пример, ResultProvider и картинку публикации. Добавить атомарность/видимость/порядок и data race. Сводка HB: program order, unlock/lock, volatile, start/join, транзитивность. Отдельно: volatile не делает ++ атомарным; специальные гарантии final требуют корректного конструирования. |
| Перед прикладной частью | Кратко объяснить jcstress: actors/outcomes, разрешённый и запрещённый исход; ненаблюдение не доказывает невозможность. Встроить в существующие примеры, без отдельной длинной лекции об инструменте. |
| После теории | Добавить постановку задачи согласованного снимка котировок и переход в IDE. Один писатель собирает immutable-снимок локально, публикует volatile-ссылку; show читает одну версию, exit отменяет и ждёт работника. |
| Финал | Краткие итоги, вопросы, спасибо. |

## Оформление

Адаптировать оригинал к серо-жёлтому оформлению текущих семинаров, сохранив его иллюстрации
и последовательность раскрытия. Не вкладывать одно окно кода в другое. Код — читаемые скриншоты,
рядом только необходимые тезисы. Сохранять тематические перебивки; не дублировать объяснения.
Не добавлять ссылки на демо, отдельный чек-лист семинариста, слайды самостоятельного чтения или PDF.

## Соответствие коду

- Жизненный цикл: `ThreadStatesDemo`, ожидания: `ParkingDemo` и `WaitingDemo`.
- Прерывание и I/O: `InterruptDemo`, `BlockingIoDemo`.
- Необработанное исключение: `UncaughtExceptionDemo`.
- Двойное списание и synchronized: `AccountRaceDemo`.
- ResultProvider с volatile-флагом: `PublicationDemo`; ошибочный вариант — `PublicationPlain` в jcstress.
- Исходный опыт с двумя переменными: `DekkerPlain` / `DekkerVolatile` в jcstress.
- Атомарность и final: `IncrementPlain`, `IncrementVolatile`, `FinalPublication`.
- Проект: `MarketSnapshot`, `SnapshotService`, `SnapshotCommand`.

Имена классов приведены для подготовки семинариста; на слайды их переносить не нужно.
